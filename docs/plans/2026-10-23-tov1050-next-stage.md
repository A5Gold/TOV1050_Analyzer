## 建議與相容性邊界

繼續以獨立的 TOV1050 專案開發，透過輸入及 metadata adapter 使用 TOV640 的 canonical detector/report 契約。先建立可重現的相容性測試，再考慮抽出共用核心。TOV640 原專案、EAL/TML workbook 與資料庫不在修改範圍。

| 方案 | 優點 | 成本／風險 | 決定 |
|---|---|---|---|
| 獨立產品 + adapter + 契約回歸 | 保留既有 EAL/TML，讓新線與 CSV 差異有明確邊界 | 需追蹤兩邊核心版本差異 | 現階段採用 |
| 立即合併為單程式雙產品設定 | 長期可減少重複維護 | UI、seed、line/session、打包與資料庫可能互相影響 | 暫緩 |
| 立即抽出 shared-core 套件 | 核心版本一致 | 尚無完整 golden regression，難證明重構未改判定 | S1 通過後再評估 |

相容指相同 canonical 量測、metadata、context 經同版判定後，exception 分組、L1/L2/L3、FromM/ToM、peak、ID 與報表欄位語意相同。不同線的閾值不同，不能要求 TOV1050 與 EAL/TML 對不同原始資料產生相同結果；CSV 與 datac、UT/DT 與 UP/DN、不同 workbook 也不直接互換。

## 已知風險及需要的輸入

1. DRL/PL 沒有 batch-04 核准候選；保留目前 long config 不等同已完成同級人工審閱。由開發端先輸出審閱表，再由使用者確認真實範圍及 PL 方向語意。

3. detector 歷史 catch/fallback 可能掩蓋 mapping 失敗；S2 在 TOV1050 入口 preflight 阻擋，保留 TOV640 判定核心。
4. wide 設定檔仍保留稽核內頁；設定編輯與 package 必須明確保護與篩選。現有 package 對 config 使用 `**/*`，可能帶入備份、legacy fixture 或本機 seed，須在 S6 改成 allowlist。
5. 目前只有部分 line 的實際 sample；逐組確認 fixture 可用性及代表性，缺項要標示。效能數值及 SLA 尚未實測，不宣稱已達 90 萬筆互動目標。
6. 現有已啟動程序可能快取 metadata；重新啟動分析程式後才保證讀取本次檔案。已打包的舊 exe 不會因 repo config 替換而自動更新。
