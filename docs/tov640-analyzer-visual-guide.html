系統總覽

TOV640 Analyzer 的核心任務是把原始量測、既有 metadata、歷史比對結果、以及資料庫中的追蹤紀錄串起來， 最後輸出異常告警、重複比對、追蹤建議、磨耗趨勢與 stagger 計算結果。 系統定位是單機、離線優先的桌面工具：Electron 管理桌面容器與 Python backend lifecycle， React + Vite 負責互動介面，FastAPI 提供分析、計算、匯出與資料庫 API，重型工程計算集中在 Python backend。

Variable Naming

這些欄位在不同模組之間反覆出現。理解它們的語意，比記 UI 欄位名稱更重要。 Backend canonical 多為 snake_case；分析報表、compare UI 與 Excel 仍保留 FromM、 MaxValue、Exception Type 這類 legacy/display shape。看到大小寫不一致時，應以資料流位置判斷語意。

聚合量測值

height_min：四路 height 最低值 height_max：四路 height 最高值 wear_min：四路 wear 最低值 wear_max：四路 wear 最高值 stg_max：四路 stagger 最大正值 stg_min：四路 stagger 最小負值

區段與峰值

FromM / ToM：異常區段起迄 length：區段長度 maxValue：該區段最壞值 maxLocation：最壞值所在 chainage

Trend 判讀

record_points：各日期實測點 trend_points：各日期 fitted 點 trend_next：決策參考 fitted 值 目前實作等同 trend_points[0]，不是下一週期外推。 logic_1：是否碰到 L2 threshold logic_2：實測與 fitted 差距是否超過 tolerance

Stagger 計算

chi：本次計算使用的定位 chainage spt_a / spt_i / spt_b：前中後支點 span_ai / span_ib：左右 span k_eq：等效風係數 allowable：允收值 short_circuit：是否套用短路通過規則

1. L1 / L2 / L3 Threshold 的 Exception Alarm

這一段描述的是系統怎麼把原始量測點先轉成「同一個 chainage 的最壞值」，再對照 metadata 的 threshold 形成正式異常區段。

Purpose

把 Height、Wire Wear、Stagger 量測轉成有等級、有範圍、有 ID 的 exception alarm。

Input

.datac 解析後 DataFrame、boundary / threshold metadata、line / section / track / date。

Output / Action

輸出 Low Height、High Height、Wire Wear、Stagger Left、Stagger Right 異常表。

Core Logic

Step 1
Map Class、Track Type、Overlap、Tension Length、Landmark
Step 2
預先計算 height_min、height_max、wear_min、wear_max
Step 3
Stagger 再計算 stg_max 與 stg_min
Step 4
以 gatekeeper 過濾點，再把連續點群組成區段
Step 5
逐區段判斷 L1 / L2 / L3 並產生 exception ID

Decision Conditions

演算法
條件
等級輸出
Low Height / Wire Wear
先抓每列最小值；gatekeeper = max(L1, L2)；值越小越嚴重
先檢 L1，再檢 L2
High Height
先抓每列最大值；gatekeeper = min(L1, L2)；值越大越嚴重
先檢 L1，再檢 L2
Stagger Left / Right
依 Track Type = Tangent / Curve 讀 threshold；用 abs(maxValue) 比 L1/L2/L3
先檢 L1，再檢 L2，最後檢 L3
Scalar gatekeeper min-mode : alarm when row_value <= max(L1, L2) max-mode : alarm when row_value >= min(L1, L2) stagger : alarm when left >= min(L1,L2,L3) or right <= -min(L1,L2,L3)

Visual Scenarios

No Alarm

仍在 gatekeeper 之外

量測點沒有跨過最外層門檻，這一列不會進入異常群組。

  • Low Height / Wear 沒有低於 gatekeeper
  • High Height 沒有高於 gatekeeper
  • Stagger 絕對值沒有超過最小 threshold
L2

區段成立，但只到 L2

連續點已形成區段，最壞值跨過 L2，尚未跨過 L1。

  • 先過 gatekeeper 才能成區段
  • 分類階段先檢 L1，不成立才落到 L2
  • 輸出 Threshold Value = L2
L1 / L3

高嚴重度或 stagger 邊界

Height / Wear 會升到 L1；Stagger 則可能落在 L1、L2、或僅 L3 的邊界警示。

  • Height / Wear 沒有 L3
  • Stagger 才有 L3
  • Curve / Tangent 會影響 stagger threshold

2. Repeat 配對

Repeat 配對不是單純看區段有沒有交集，而是同時要求「同類型 + 區間有交集 + 兩個 peak 都落在交集內」。 它不是兩兩獨立比對後合併，而是以最新報表為主軸，逐期向舊報表延伸 repeated chain。

Purpose

確認最新報表中的異常，是否能沿著多期報表一路存活成 repeated chain。

Input

最新 Exception Report 累積器 df_chain，以及下一份更舊的報表 df_new。

Output / Action

保留最新報表欄位，新增 Previous 1、Previous 2、Previous N 與對應 metadata。

Core Logic

Step 1
把舊版欄位與新版欄位統一成 FromM / ToM / maxLocation / id
Step 2
先用 exception type 做 inner join
Step 3
算交集 i_start = max(FromM)、i_end = min(ToM)
Step 4
驗證最新與舊報表兩邊的 peak 都落在交集內
Step 5
去重後保留最新報表列，將舊報表 ID 掛到 Previous N
Repeat condition same exception type AND i_start <= i_end AND maxLocation_master in [i_start, i_end] AND maxLocation_target in [i_start, i_end]

Repeated Chain

Base
Latest Report

作為 accumulator，保留最新報表欄位。

Hop 1
Previous 1

同類型、區間交集、雙方 peak 都在交集內。

Hop 2
Previous 2

只拿上一輪存活者繼續往舊報表比對。

Result
Previous N

能一路存活的列才是 repeated result。

Visual Scenarios

Valid Match

交集成立，兩個 peak 都在交集內

Latest Previous Peak Marker
Gap

區段沒有交集

沒有交集就直接淘汰，不進入 repeated chain。

Peak Drift

有交集，但 peak 飄出有效區

交集不是唯一條件。只要任一邊 peak 不在交集內，也不能算 repeated。

4. Wear Calculator Analysis

The Wear Calculator now has two feature tabs: Analysis and Wire Wear Records. The Analysis tab aggregates an upload batch into one WearResult per Line and Tension Length name before records are saved.

Batch Aggregation Flow

Upload batch
Read one or more Exception Report files and collect ChartData records.
Resolve TL
Use chainage metadata to resolve Tension Length; fall back to the ChartData TL when metadata is unavailable.
Merge same TL
The same Tension Length name is merged across date, session, track, file, and metadata rows.
Set output date
The output cycle date is the latest date in the upload batch.
Save result
Save one cycle value per merged Tension Length.

Grouping Rule

The aggregation key is line + tension_length. It no longer splits one TL into multiple analysis rows only because the raw rows came from different tracks, files, dates, or sessions.

Track / Section Output

If the merged TL crosses both UP and DN, the output track is shown as Siding. If multiple sections are merged, the output section is shown as Mixed.

Output Fields

The result includes avg_wear_min, sd, wear_percentage, dates, record_points, and merged from_m / to_m.

4. Wire Wear L2 Trend

Trend 只分析 L2 Wire Wear，而且預設只看「最新週期、ACTION 空白」的候選。若另附 n_Repeated，則還要先通過 ID 配對。

Wear / Trend Parser 分流

Exception Report Excel
讀取 Summary / Wire Wear / ChartData
Parser
轉成 WireWearRecord[] 與 ChartDataRecord[]
/api/calculation/wear
依 tension length 匯總 WearResult
/api/calculation/trend
只針對 L2 Wire Wear 產生 recommendation
/api/calculation/upload
combined endpoint，同時回 wear 與 trend

Purpose

判斷 L2 Wire Wear 是不用動作、需要現場驗證，還是確認為有效 L2。

Input

WireWearRecord[]、{task_run_date: ChartDataRecord[]}，以及可選的 RepeatedSummaryRecord[]。

Output / Action

輸出 record_points、trend_points、logic_1、logic_2、recommendation。

Core Logic

Case A
沒有 n_Repeated：保留最新週期、ACTION 空白、Level = L2 的 Wire Wear
Case B
有 n_Repeated：還必須 ID 在 repeated summary 中出現
By Date
對每個日期，在 from_m..to_m 區間內取 wear_min 最小值
Regression
用有效日期做線性回歸，產生 trend_points
Decision
依 logic_1 / logic_2 轉成 recommendation
Trend recommendation logic_1 = fitted_value <= 10.2 logic_2 = abs(latest_record_point - fitted_value) > 0.2 if logic_1 == false -> no action required if logic_1 == true and logic_2 == true -> verify on site if logic_1 == true and logic_2 == false -> confirmed valid L2

Decision Conditions

Scenario
條件
Recommendation
未碰到 L2 threshold
logic_1 = false，即 fitted 值高於 10.2
no action required
碰到 threshold，且和實測差很大
logic_1 = true 且 logic_2 = true
verify on site
碰到 threshold，但趨勢與實測一致
logic_1 = true 且 logic_2 = false

Visual Scenarios

No Action

代表目前趨勢參考值還沒進入 L2 判定區，系統不建議採取動作。

5. Average Wire Wear Value of Each Tension Length

這段不是異常分類，而是把 ChartData 中每個 tension length 的 wear_min 匯總成可比較的統計結果。 Wear 與 Trend 共享 Exception Report parsing，但決策目的不同：Wear 做 tension length 統計，Trend 做 L2 recommendation。

Purpose

為每個 tension length 算出平均磨耗、標準差、磨耗百分比，以及日期序列點。

Input

ChartDataRecord[]，以及可選的 tension length lookup metadata。

Output / Action

輸出 WearResult：avg_wear_min、sd、wear_percentage、record_points。

Core Logic

Step 1
若有 metadata lookup，先用 chainage 落點與 track_type 去 resolve segment
Step 2
若 lookup 沒命中，就把原始 tension_length 以逗號拆開 fallback
Step 3
展平成 task_run_date / chainage / wear_min / tension_length 列
Step 4
按 tension length 分組，再按日期算平均點 record_points
Step 5
算整體平均、標準差、磨耗百分比、範圍 from_m..to_m
Wear percentage r = mean_remaining R = 6.6 worn_area = acos((r - R)/R) * R^2 - R * sin(theta) * (r - R) wear_percentage = worn_area / 120 * 100

Visual Scenarios

Metadata Match

精準落在 metadata 區段

可直接取得正確的 tension_length、from_m、to_m，同時優先比對 track_type。

Fallback Split

lookup 沒命中，用原始字串拆段

如果 metadata 查不到，就把原始 Tension Length 欄位用逗號拆開，區段邊界則退回 chainage 最小值與最大值。

Mixed Track Merge

同一 TL 來自多個 track

若同一個 tension length 橫跨多個 track，輸出 track 會標成 Crossing/Siding，提醒這是混合來源。

6. Stagger Calculation

Stagger 計算分成兩層。第一層先決定哪些 summary row 可以進入計算；第二層再根據支點、量測值、風係數與公式判斷 pass / fail / n/a。 這是獨立於 wear/trend 的 calculation 子模組；除了 summary，也輸出 trace，讓支點、span 與公式判斷可追溯。

Purpose

把 Stagger Left / Right 的異常區段轉成 span 級判斷，並附上可追溯 trace。

Input

Summary row、ChartData channels、support metadata、wind factor、可選 n_Repeated summary。

Output / Action

輸出 results + traces + warnings，並標示 case_type 與 trace_status。

Core Logic

Step 1
選候選：只保留 L1 / L2 且類型是 Stagger Left / Right
Step 2
Case A 用 Exception Report；Case B 必須 repeated summary 有相同 ID，且可覆蓋 max_location
Step 3
依 chi 找到 spt_a / spt_i / spt_b，若缺支點則輸出 partial trace
Step 4
從最近列抓 A/I/B 量測值，再算 k_eq、b、p、s、e、allowable
Step 5
兩個 span 各自判定後彙總為 overall pass / fail / n/a
Span decision b = 0.6137 * 0.8 * 1.08 * (34.3 * k_eq)^2 * 0.0132 * span^2 / (32 * tension) p = abs((stg_x + stg_i) / 2) s = abs(stg_x - stg_i) e = s^2 / (16 * b) allowable = 505 - (b + e) - height_correction if s >= 4 * b -> pass_short_circuit else if p <= allowable -> pass else -> fail
